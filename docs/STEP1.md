## 环境决定

使用本机 `D:\conda\python.exe`（3.13.5）创建 `project/.venv`。没有更改 Conda base 的依赖，也没有配置系统服务。项目依赖安装在隔离环境内；本机约 16 GB 内存和 16 逻辑处理器可完成当前场景。GPU 已检测到但未使用。

原环境可读到 Matplotlib、NumPy、Pillow、NetworkX、Pytest。项目中仅安装绘图所需依赖，并保存完整版本锁定。CPU 信息通过 Windows 注册表读取，内存通过 `GlobalMemoryStatusEx` 读取；系统 CIM 查询受到权限限制，因此没有把该查询失败当作硬件缺失。

## 下一步边界

静态 A* 仅解决单车固定地图寻路。目前遇到多辆车或多个任务直接报错，防止在没有预约表时输出假冒无冲突的多车结果。第 2 步需要实现：

1. 预约未来顶点及有向边，检查同格占用与对向交换。
2. 搜索状态加入时间，动作允许等待，取放货和完成后空闲占用也进入预约。
3. 覆盖抢同格、对向交换、窄道会车、取货点占用和无路重试的小案例。

此后才扩展任务队列与 B0、B1、P。不能把当前 `conflict_count=0` 解释为多车安全证明，不能把单车最短路径称为多车最优调度。
